## Context

The first real walk-forward backtest (2026-03-01 → 2026-09-11, 12 months of FYERS data now cached from 2025-09-12) failed the M6 gate badly:
- 58 trades, 31% win rate, **expectancy −0.42R** (−0.30R before slippage), profit factor 0.48, **max drawdown 28R** (≈₹16,800 on ₹20,000 capital).
- 70% fill rate (25 missed entries).
- By strategy: orb 27 trades, 44% win, −0.15R; gap 13, 23%, −0.42R; vwap 8, 25%, −0.52R; pullback 6, 0%, −1.37R; range_breakout 3, 33%, −0.38R; pdhl 1, −1.29R.

From the exported trades:
- Many losers never went meaningfully in favour (MFE ≈ 0–0.3R), which points to weak entry confirmation.
- The flat ₹50 cost turns a −1R stop into −1.2 to −1.4R on small positions.
- Several trades drift to the 15:00 hard exit near flat.
- About half of winners are stopped out after the partial exit.

The Streamlit dashboard also isn't good enough. You chose:
- **Strategy first**, using diagnose → tune → walk-forward validation, so the tuning doesn't just fit this one period.
- **Actual FYERS intraday charges** instead of the flat ₹50.
- **FastAPI + React (Vite)** for the new UI.

Unchanged constraints:
- Alerts only; never place orders.
- Max 3% risk per trade and 2 trades/day.
- The shared `run_cycle` stays the single decision path for both live and backtest.
- The dashboard only reads SQLite and writes through narrow controls, bound to 127.0.0.1.

Operational note: the earlier failed command was only a PATH issue. Run `.venv/bin/tradalgo …` or activate the venv.

## Phase A — Strategy edge

### A1. Diagnostics report (read-only analysis)
New `tradalgo/backtest/diagnostics.py` plus a `tradalgo diagnose --run-id N` command. It is pure pandas over `backtest_trades`, `signals` and `decisions`, and prints and saves a markdown report under `data/reports/`. Per strategy, and per regime / hour of day / direction, it shows:
- Trades, win rate, expectancy.
- R distribution by exit reason (stop_hit / runner_exit / hard_exit).
- **MFE histogram**: how many losers reached +0.5R and +1R before stopping, which separates exit-rule problems from entry problems.
- Gross-vs-net drag (costs, slippage).
- Missed fills by strategy.
- Rejected-signal counts by rejection reason (room, EV, limits).

This reuses `backtest/metrics.py compute_metrics` and the existing schema. No engine changes.

### A2. Realistic cost model (replaces flat ₹50)
- New `tradalgo/risk/costs.py`: `intraday_charges(buy_value, sell_value) -> float`. It covers brokerage per executed order (min of ₹20 or a % of turnover), STT on the sell side, exchange transaction charges, SEBI fees, stamp duty on the buy side, and GST on brokerage + exchange + SEBI.
- Every rate goes in a new validated `costs:` section in `config.yaml` / `config.py`. Defaults come from FYERS's published equity-intraday charges, and the README tells you to verify them against the FYERS charges page.
- Use the same function in every cost path:
  - `risk/validator.py` cost_r.
  - `backtest/paper_broker.py`: per leg, on the actual buy/sell values including the partial exit.
  - `engine/cycle.py route_events`: net R for the daily loss limit.
  - `engine/live_sink.py` for net R.
- This deliberately replaces the spec's flat ₹50, per your decision, and is recorded as a ruling.
- Tests: hand-computed charges for a small and a large trade, and a check that backtest net R changes consistently.

### A3. Make strategy and exit parameters config-driven
Detector thresholds are currently keyword defaults.
- Add an optional `params: {}` dict per strategy in `config.yaml` (`strategies.<name>.params`), validated as numbers.
- `strategies/registry.py detect_all` passes these params into each detector.
- Add exit tunables to `risk` / `position_management`: `partial_exit_at_r`, `partial_exit_fraction`, `breakeven_after_partial` (bool), `trail_bars`, `stop_atr_min` / `stop_atr_max`, `last_entry_time` per strategy (already `window_end`).
- Wire them into `engine/positions.py` and `strategies/common.py`, since the final review removed the dead knobs and now they must actually be used.
- Defaults equal the current values, so existing tests and backtest numbers are unchanged. That is verified by re-running `test_replay` / `test_lookahead` with no assertion edits.

### A4. Walk-forward parameter sweep
New `tradalgo/backtest/sweep.py` plus a `tradalgo sweep --grid grid.yaml --train-from --train-to --test-from --test-to [--workers N]` command.
- **Grid:** a YAML of candidate values per strategy param, per exit param, plus enable/disable per strategy. It expands to combinations, capped with random sampling when the grid is large.
- **Speed:** candles are preloaded once per process and combinations run with `multiprocessing` (one worker per core). It calls `backtest.replay.run_backtest` in memory with a no-persist sink, so there are no `backtest_runs` rows per combination; only the final chosen configuration is saved as a normal run. Replay is reused unchanged.
- **Selection:** rank on the **train** period only, requiring at least 40 train trades; the score is expectancy minus a drawdown penalty. The top-K are then evaluated on the **test** period. The report shows train vs test side by side and flags big train→test decay as overfitting.
- **Default split:** train 2025-10-06 → 2026-04-30, test 2026-05-01 → 2026-09-11.
- Output: `data/reports/sweep-<ts>.md` plus a `recommended.yaml` params block you review and paste into `config.yaml`. The sweep never edits config itself.

### A5. Structural fixes driven by A1 evidence
Implement only what the diagnostics support; each is config-toggleable and joins the sweep grid:
- **Entry confirmation.** Candidates:
  - Require 15-minute trend alignment for non-counter-trend strategies.
  - Minimum RVOL on the trigger bar.
  - Close in the top/bottom 25% of the bar's range.
  - Skip the first N minutes after the open for vwap/pullback.
- **Hard-exit drift:** an earlier `window_end` for late-day strategies, and an optional time stop that exits if the trade hasn't reached +1R within N bars.
- **Missed fills:** make `band_fraction_r` a sweepable value, and add an option to size and alert as a stop-limit trigger so a manual fill is realistic.
- **Disable any strategy that is still negative out-of-sample after tuning** (config `enabled: false`), and record why.

### A6. Gate
The new gate is expectancy > 0R **on the out-of-sample test period** after real charges and slippage, with at least 100 trades across train + test, and max drawdown at or below `capital.daily_loss_limit_r × 5` (configurable). Only a configuration that passes this is written into `config.yaml`. If nothing passes, the report says so plainly and live alerts stay untrusted. The system is not loosened to force a pass.

## Phase B — FastAPI + React dashboard

### B1. JSON API (`tradalgo/api/`)
- A FastAPI app using `uvicorn`, bound to `settings.dashboard.host` (loopback validator kept). It serves `/api/*` and the built SPA from `web/dist`.
- Endpoints are thin wrappers over the **existing pure functions** in `tradalgo/dashboard/queries.py` and `controls.py`, moved to `tradalgo/api/queries.py` and `controls.py` unchanged:
  - `GET /api/now`: Now-strip state via `theme.now_strip_state` logic, moved into `api/now.py`.
  - `GET /api/shortlist?date`, `/api/signals?date`, `/api/positions`, `/api/alerts?status&date`, `/api/journal?from&to&strategy&symbol`, `/api/analytics`, `/api/health`.
  - `GET /api/backtests`, `GET /api/backtests/{id}`: metrics, trades, equity curve, plus the A1 diagnostics.
  - `POST /api/backtests` (uses `validate_backtest_params`), `POST /api/backtests/{id}/cancel`.
  - `POST /api/alerts/{id}/resend`; `POST /api/kill-switch {on}`.
  - `GET/PUT /api/settings`: Settings validation plus a timestamped backup, via `controls.save_settings`.
  - `GET /api/candles/{symbol}?date`: from `CandleCache.load` with `provider=None`, read-only, plus that day's signal levels.
  - `GET /api/sweeps`, `GET /api/sweeps/{id}`: sweep reports from A4.
- Pydantic response models. No FYERS calls and no engine in-process; the global constraint stays.
- Deps: `fastapi`, `uvicorn[standard]`. `httpx` is added to dev deps for tests.
- Tests: `tests/test_api_*.py` with FastAPI `TestClient` on the seeded-DB fixtures ported from `tests/test_dashboard_queries.py` / `test_dashboard_controls.py`. Cover every endpoint on empty and seeded DBs, validation failures (400), loopback-only config, and the guard test still green.

### B2. Design plan (frontend-design skill, before any UI code)
Written to `docs/superpowers/plans/…-dashboard-v2-design.md`:
- Subject / audience / primary job: "what needs my action now", then "is the strategy working".
- Color tokens (4–6 named hex, WCAG AA verified), one type family with tabular figures, layout ASCII per page, and the single bold element.
- An explicit review against the skill's defaults list, recording what was revised and why.
- Reuse what survived the last review: amber only for "needs action", muted gain/loss only on R/₹ numbers, cool neutral paper.

### B3. React app (`web/`)
- Vite + React + TypeScript and TanStack Query, polling 15s for Today/Positions and 3s while a backtest or sweep is running.
- React Router pages mirroring today's: Today (Now strip, shortlist, signals), Positions, Telegram, Backtest (queue form, runs, equity/R-histogram, diagnostics, gate verdict), Sweeps (train vs test table, overfit flags), Journal (CSV export), Analytics, Health, Settings (validated form).
- Charts per the dataviz skill: TradingView `lightweight-charts` (Apache-2.0) for candles with entry/SL/2R/3R lines, and a small SVG/visx component for the equity curve and R histogram.
- No UI component kit that imposes the generic SaaS look. Hand-built components on the B2 tokens, visible focus, and reduced-motion respected.
- Tests:
  - `vitest` for the pure logic (Now-strip text, gate verdict, formatters).
  - A build check.
  - A Playwright smoke run against the running API with a seeded DB that screenshots every page, used for the frontend-design self-critique and saved to `data/reports/ui/`.

### B4. Cut over
- `tradalgo dashboard` runs `uvicorn tradalgo.api.app:app` via `sys.executable -m uvicorn`, serving `web/dist`. A `tradalgo dashboard --dev` flag proxies to the Vite dev server.
- Update `launchd/com.tradalgo.dashboard.plist`, `scripts/run_local.sh` and the README. The README gets a `npm ci && npm run build` step.
- After parity is confirmed by the Playwright smoke run, delete `tradalgo/dashboard/` (Streamlit), `.streamlit/`, the `streamlit`/`plotly` deps and the Streamlit tests.
